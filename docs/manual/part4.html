Running jobs

What happens once you press Start: following a batch while it works, stopping it without losing anything, how Studio shares your graphics card between stages, and leaving a long chapter to run on its own.

16 The job queue and progress #

A job is one stage working through a folder of clips: a batch. Press Start and the stage works through every clip in its input folder, one after another, without you doing anything more.

The action bar

The bar at the bottom of the page shows the running job:

  • The progress bar fills as the clip is worked on. Some stages work in steps, and the bar starts again for each: Merging, for instance, matches the grain first, then renders, then splits the left and right eyes if you asked for that.
  • The line under it says what's happening: which clip, and how far through the batch. DepthCrafter and Inpainting also show the live numbers: which chunk or window of the clip they're on, and how long each step takes (s/it, seconds per step).
  • The status line at the very bottom of the window says which stage is busy, whichever tab you're looking at, so you can look around the other stages while a job runs.

Upcoming Jobs

DepthCrafter, Splatting, Inpainting and Merging each list the clips the batch will work through, under Upcoming Jobs, with a Batch Progress counter above them. On DepthCrafter and Inpainting the list sits to the right of the settings.

  • Each row shows the clip's length and its shape: 120 frames · 1.85:1.
  • While a job runs, each row has its own bar: the clips already done are full, the one being worked on fills up, the rest are empty. The clips the run has finished turn light green, and stay green until the next run starts.
  • When nothing is running, click a row to load that clip into the preview (Splatting and Merging: DepthCrafter and Inpainting have no preview).
  • Tick clips to work on just those: Process Selected runs the batch on the ticked clips only. Start still runs them all.
  • Move to Finished moves the ticked clips into the finished folders without processing them: handy for clips you've decided to skip. Restore Finished brings them back.
  • Right-click a clip for quick jobs on that clip alone. In DepthCrafter: Process This Clip Now and Move to Finished. In Splatting: Splat This Clip Now (the same as Single, without loading it first) and Rerun in DepthCrafter, which switches to DepthCrafter with that clip as its input and the folder its depth map lives in as the output: change the settings and press Start, and the new map replaces the old one; and Rerun with Video Depth Anything, which does the same on DepthCrafter's VDA tab (the DepthCrafter map moves into a DepthCrafter folder beside it). In Inpainting: Inpaint This Clip Now and Move to Finished. In Merging: Merge This Clip Now and Move to Finished.
  • Test Render, in every stage's right-click menu, runs that one clip as "This Clip Now" does but into a Test Renders folder inside the stage's output folder, so the real output is never overwritten. It moves nothing to finished and isn't passed on to the next stage as the job's result. Testing the same clip again replaces the earlier test.
  • A clip the job just finished (its row green) also offers Send to Splatting, Send to Inpainting or Send to Merging, to take that one clip on through the pipeline without running the rest of the chapter. The next stage opens with what this one made as its input (DepthCrafter's depth map with its source clip, Splatting's Lo-Res splat, Inpainting's inpainted clip) and, when you're working by chapter, that chapter's folders for its output and its other inputs. Your settings are left alone: check them and press Start.
  • The same menu plays the files that go with the clip in your usual video player: Play Source Clip (DepthCrafter, Splatting), Play Depth Map (Splatting), Play Lo-Res Splat and Play Hi-Res Splat (Inpainting), and Play Inpainted Clip, Play Original and Play Splat (Merging). These work during a job too.
  • Under them, Open ... in Explorer opens a File Explorer window with that file selected, one for each kind of file that goes with the clip: Open Source Clip in Explorer and Open Depth Map in Explorer in Splatting, the Lo-Res and Hi-Res splats in Inpainting, and so on. Edge Fill's right-click offers the merged clip and its Hi-Res splat the same way.

When a batch ends

A message pops up saying how it went: how many clips were done, and how many failed or were skipped. If nothing could be made at all (an empty folder, missing model files), it says why instead. The next stage's Import from … button then offers this batch's output, so you can carry straight on. With a project picked in the title bar, an Import only offers that project's jobs, and fills every folder from the same chapter, the output folder included.

The line under the progress bar then says how long the whole batch took, from Start to the end: Completed in 1h 02m 13s, or Stopped after … if you stopped it. It stays until that stage's line moves on. The messages that popped up are kept in the bell beside the gear, so one you missed while away can still be read.

If Studio's window is minimized when a job finishes, Windows shows a notification with the same message, for every stage, Scene Cut included. Click it to bring Studio back. Nothing extra appears while the window is up.

Good to knowStudio keeps its animations still while a job runs. Every redraw costs the graphics card a little, and on a long job that adds up, so the window stays calm until the job is done.

17 Stopping safely #

There are two ways to stop: gently, keeping everything finished so far, or now.

Stop After Clip: the gentle way

Splatting, Inpainting and Merging have a Stop After Clip button. Press it and the clip being worked on is finished properly, then the batch stops. It reads Stopping After Clip until then; press it again if you change your mind. The rest of the folder is left for the next Start.

Stop

Stop asks first, and offers a choice:

  • Stop now: the clip being processed is cut off and its unfinished output is thrown away. Clips already finished are kept.
  • The safe option, which depends on the stage:
    • Splatting, Merging, Inpainting: Stop after this clip (the same as Stop After Clip).
    • Inpainting, while it works through a clip in chunks: Stop after this chunk. The piece being worked on is kept, and the next Start on that clip carries on from there.
    • DepthCrafter: Stop after this segment, when it's processing in segments. Resume carries on from the next segment.
  • Keep running: nothing changes.

Carrying on later

You never lose finished work. Every finished clip is moved into a finished folder (Part 1), so pressing Start on the same chapter again carries on with the clips that are left. A clip cut off by Stop now is never left behind looking finished: its unfinished file is thrown away.

Closing Studio during a job

Closing the window while a job runs asks first. Quit now stops the job the same way as Stop now, then closes Studio. To let the clip finish first, press Stop After Clip and close Studio once it has stopped.

18 GPU memory #

Every stage runs on your graphics card and needs a lot of its memory (VRAM), so Studio looks after it for you.

One job at a time

Only one stage can run a job at once. Start another while one is running and Studio tells you to wait for the first to finish. This includes Scene Cut and the Depth Map Editor's renders.

When a job starts, any other stage still holding the graphics card, such as another stage's preview, lets go of it first, so the job has the memory to itself. A preview that was put away comes back once the job is over.

The VRAM meter

The VRAM meter at the top right shows how much of your card's memory is in use: by every program, not only Studio. It updates every couple of seconds. Click it for the details: how much is free, and how much Studio itself is using.

TipGames, video players and browsers use graphics memory too. If a job runs out of memory, or crawls, close them, or check the meter to see how much is left.

Running out of memory

Each stage's "When something isn't right" table in Part 2 says which settings to lower. In short: a smaller size or batch, fewer frames at a time, or an offload mode that keeps part of the model in normal memory instead.

19 Unattended runs #

A chapter can take hours, and Studio is built to work through it on its own while you're away.

Before you leave it

  1. Set every clip up first. Go through the clips in the preview and save each one's sidecar (Splatting, Merging), so the batch uses your settings for every shot.
  2. Check the first clip. Let one clip finish and look at it before leaving the rest to run: a wrong setting is cheaper to catch on one clip than on fifty.
  3. Stop Windows from sleeping. A sleeping PC pauses the job. In Windows' power settings, set Sleep to Never while you convert (it is okay for the monitor to be turned off).
  4. Close what you don't need, especially anything that uses the graphics card.

When you come back

  • The message that popped up when the batch ended says how many clips were done and how many failed.
  • The console (Ctrl+`) has the whole run, clip by clip, each one starting with a separator line. A failed clip says why there.
  • Studio also writes everything to studio_last_run.log in your Studio folder. The run before that is kept as studio_last_run.prev.log, so a log is still there after Studio is started again.
  • Clips that failed are still in the input folder (they weren't moved to finished), so pressing Start again tries just those.
If Studio closed by itselfWhen Studio ends because of an error, a window offers to open the log. Keep that file: it's what explains what happened, and the first thing to send when asking for help.
